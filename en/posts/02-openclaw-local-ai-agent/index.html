Deploying OpenClaw in Practice: Setting Up a Personal AI Assistant with Local Large Models

A complete deployment guide for OpenClaw 2026.9.5 on Windows, integrating with a local Ollama instance running Qwen2.5-14B, detailing the challenges encountered.
September 21, 2026 · 3 min · Local AI Lab

What is OpenClaw#

OpenClaw is an open-source AI Agent Gateway that runs on your own machine, connecting chat channels (Telegram, Discord, Lark, Web UI, etc.) to large models. It is licensed under MIT and has over 100,000 stars on GitHub.

Its value lies in: you send a message, it calls the model, executes tools, maintains sessions, and retains memory—essentially, it upgrades “ollama in the command line” into a truly functional assistant.

System Requirements#

  • Node.js ≥ 24.16 (Note: Node 22 LTS is insufficient and will be rejected by the preinstall script)
  • Windows 10/11
  • A local or remote Ollama instance

Installation Steps#

1. Install Node.js 24#

Download the Windows zip version from nodejs.org, extract it to C:\nodejs, and add it to the user PATH.

[Environment]::SetEnvironmentVariable('Path', "$env:Path;C:\nodejs", 'User')

2. Install OpenClaw Globally#

npm install -g openclaw@latest

Pitfall 1: npm 11 introduces a allow-scripts security mechanism that defaults to skipping postinstall scripts for native modules like koffi. You must execute:

npm install -g --allow-scripts=openclaw,@google/genai,koffi,tree-sitter-bash,protobufjs openclaw@latest

Otherwise, the startup will fail due to missing native bindings.

3. Configure Local Ollama#

Edit C:\Users\<you>\.openclaw\openclaw.json:

{
  "gateway": { "mode": "local" },
  "models": {
    "providers": {
      "ollama": {
        "baseUrl": "http://127.0.0.1:11434",
        "models": [
          {
            "id": "qwen2.5:14b",
            "contextWindow": 32768,
            "params": { "num_ctx": 32768, "keep_alive": "15m" }
          }
        ]
      }
    }
  },
  "agents": {
    "defaults": { "model": { "primary": "ollama/qwen2.5:14b" } }
  }
}

Pitfall 2: The OpenClaw Ollama provider must use the native API (baseUrl without /v1). Using the OpenAI-compatible /v1 endpoint will cause tool calls to fail.

Pitfall 3: Not writing the API key in the configuration file is not enough—it exists in the local SQLite authentication database. The first run requires:

"ollama-local" | openclaw models auth paste-api-key --provider ollama

4. Start the Gateway#

openclaw gateway install   # Install to start on boot
openclaw gateway restart

Open your browser and visit http://127.0.0.1:18789/, log in with the token output by openclaw gateway auth-token --show, and you can chat in the Web UI.

Performance Test#

With qwen2.5:14b as the backend, on a machine with 12GB of VRAM:

  • Normal conversations run 100% on GPU, approximately 49 tok/s
  • Long context (32K) will partially spill over to memory, reducing speed
  • Agent mode (with tool calls) is fully functional, but the 14B model’s understanding of complex multi-step toolchains is inferior to that of GPT-4-level models

Conclusion#

OpenClaw is currently the most straightforward solution for turning local models into “real assistants”. The deployment process is more challenging than expected (Node version, npm security mechanisms, context window size issues), but once set up, it becomes a fully functional, self-starting local agent that can be accessed via Web UI and connected to Telegram/Lark.
