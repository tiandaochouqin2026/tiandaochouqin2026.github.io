Windows Deployment of Ollama Troubleshooting: GitHub Download Failure, Local Network Access, OLLAMA_HOST

Three real issues encountered when deploying Ollama on Windows: download failure due to domestic network, default listening only on loopback, and OLLAMA_HOST settings not being recognized after service restart.
September 21, 2026 · 3 min · Local AI Lab

Deploying Ollama locally seems like a straightforward process, but there are three unexpected issues you might encounter. Here’s a record of them.

Pit 1: Direct Download from Official Website Fails#

Symptoms: Accessing https://ollama.com/download/OllamaSetup.exe results in PowerShell errors such as Could not resolve host: github.com or Unable to connect to remote server.

Cause: The Ollama official website is just a redirect page, and the actual installation package is hosted on GitHub Releases. Accessing GitHub from domestic networks is unstable and unreliable.

Solution:

  1. First, get the latest version number from https://api.github.com/repos/ollama/ollama/releases/latest.
  2. Add a mirror prefix to the GitHub download link, for example: 
    https://ghproxy.net/https://github.com/ollama/ollama/releases/download/vX.Y.Z/OllamaSetup.exe
  3. Use curl or a browser to download the file and verify its size (Ollama installation package is approximately 1.4GB).

Pit 2: Default Listening Only on 127.0.0.1, Unreachable from Other Devices#

Symptoms: Ollama runs successfully, but http://192.168.x.x:11434/api/tags cannot be accessed from other devices, while curl http://127.0.0.1:11434/api/tags works fine on the local machine.

Cause: By default, Ollama sets OLLAMA_HOST=127.0.0.1 for security reasons, which does not expose the service to the local network.

Solution (Run as Administrator in PowerShell):

[Environment]::SetEnvironmentVariable('OLLAMA_HOST','0.0.0.0','User')

Then, restart the Ollama service for the changes to take effect. In Task Manager, end all ollama.exe processes and restart the Ollama application.

Use netstat -ano | findstr 11434 to confirm that the listening address has changed to 0.0.0.0:11434.

Pit 3: Environment Variable Set but Not Read by Service#

Symptoms: After setting OLLAMA_HOST=0.0.0.0, Ollama still listens on 127.0.0.1 after a restart.

Cause: The Ollama Windows version is a tray application (ollama app.exe), and it starts with the environment variables set at login time. After modifying the user-level environment variable, the tray application must be completely closed (right-click the tray icon → Quit) and restarted. Only restarting the command line ollama serve inherits the current shell environment, but the tray application does not.

Solution:

  • Check Task Manager to ensure there are no lingering ollama.exe processes.
  • Restart Ollama from the Start Menu.
  • Use netstat to verify.

Pit 4: Windows Firewall Blocks External Access#

Symptoms: The local machine can access http://192.168.x.x:11434, but mobile devices cannot.

Cause: The Windows Defender Firewall blocks external inbound connections to port 11434 by default.

Solution (Run as Administrator in PowerShell):

New-NetFirewallRule -DisplayName "Ollama" -Direction Inbound -LocalPort 11434 -Protocol TCP -Action Allow

To open only to the local network for security:

New-NetFirewallRule -DisplayName "Ollama LAN" -Direction Inbound -LocalPort 11434 -Protocol TCP -RemoteAddress 192.168.0.0/16 -Action Allow

Summary#

The four issues are not bugs in Ollama itself but rather common obstacles when exposing a local service to the network on Windows. Follow this sequence: use a mirror for downloading → change OLLAMA_HOST → completely restart → allow firewall rules. Once you’ve encountered these issues, you can resolve them in about 10 minutes next time.
