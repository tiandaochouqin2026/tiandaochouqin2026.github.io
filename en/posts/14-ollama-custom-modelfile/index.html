optimize local LLM deployment with system prompts, stopwords, and parameter tuning
November 20, 2026 · 2 min · Local AI Lab | Translations:
  • Zh-Cn

When deploying large language models (LLMs) locally, the Modelfile is the core configuration file that dictates the model’s behavior. It allows you to customize the model’s prompts, stopwords, and adjust parameters to achieve optimal performance. This article will provide a detailed guide on how to write and optimize your own Modelfile.

Basic Structure of a Modelfile#

A standard Modelfile typically includes the following components:

  • System Prompt: Defines the model’s startup prompt.
  • Stopwords: Defines the conditions under which the model’s output will stop.
  • Parameter Tuning: Adjusts the model’s runtime parameters.

A sample Modelfile structure looks like this:

system: "Please respond as an assistant."
stop: ["\n"]
params:
  max_tokens: 2048
  temperature: 0.7
  top_p: 0.9

Writing System Prompts#

System prompts are used to set the initial context for the model. They define the model’s behavior and output style. For example, you can specify that the model should respond in a particular tone or style.

Example:

system: "Please respond as an assistant using clear and concise language."

Command Line Example:

ollama run --system "Please respond as an assistant using clear and concise language." model-name

Applying Stopwords#

Stopwords are used to define the conditions under which the model’s output will stop. When the model’s output contains the specified stopwords, the output will cease. This is very useful for controlling the length and format of the output.

Example:

stop: ["\n"]

Command Line Example:

ollama run --stop "\n" model-name

Parameter Tuning#

Parameter tuning is a key step in improving model performance. By adjusting parameters such as max_tokens, temperature, and top_p, you can customize the model’s output behavior.

  • max_tokens: Defines the maximum length of the model’s output.
  • temperature: Affects the randomness of the model’s output; the lower the value, the more deterministic the output.
  • top_p: Controls the diversity of the output; the closer the value is to 1, the more diverse the output.

Example:

params:
  max_tokens: 1024
  temperature: 0.5
  top_p: 0.8

Command Line Example:

ollama run --params "max_tokens=1024,temperature=0.5,top_p=0.8" model-name

Conclusion#

By writing and optimizing your Modelfile, you can significantly enhance the performance and user experience of your locally deployed LLM. Through system prompts, stopwords, and parameter tuning, you can flexibly customize the model’s behavior to meet different application needs. I hope this article is helpful to you, and wish you smooth sailing on your journey of deploying LLMs locally!
