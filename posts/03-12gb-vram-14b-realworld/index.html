12GB 显存跑 14B 模型：Q4 量化、上下文窗口、CPU/GPU 混合的实测

Qwen2.5-14B 在 RTX 4070 SUPER 12G 上的显存分配实测：不同上下文长度下 GPU/CPU 比例和推理速度。
September 21, 2026 · 2 min · Local AI Lab | Translations:
  • En

问题#

12GB 显存跑 14B 模型，到底能开多大上下文？这是部署本地大模型时最关心的问题之一。本文用真实数据回答。

测试环境#

  • 显卡：RTX 4070 SUPER（12GB）
  • 模型：Qwen2.5-14B-Instruct，Q4_K_M 量化，权重约 9GB
  • 推理引擎：Ollama 0.34
  • 监控命令：ollama ps

实测数据#

上下文长度 (num_ctx) 模型占用 GPU/CPU 比例 推理速度
4096 9.5 GB 100% GPU ~49 tok/s
16384 ~11 GB 100% GPU（临界） ~40 tok/s
32768 ~15 GB 34% CPU + 66% GPU ~15-20 tok/s
65536 爆显存 大量 CPU 不可用

原理#

14B Q4 的权重约 9GB。剩下的 3GB 显存要放：

  • KV cache：每 1K token 上下文约占几百 MB（取决于模型层数和隐藏维度）
  • 激活值和临时缓冲

上下文越长，KV cache 越大。超过显存容量后，Ollama 会自动把部分层放到系统内存，通过 PCIe 交换数据——这就是为什么速度突然腰斩。

实用建议#

  1. 日常对话用 4096-8192 上下文：绝大多数聊天场景够了，速度最快。
  2. 长文档分析用 16384：12G 显存临界值，还能跑满 GPU。
  3. 代码/Agent 用 32768：必须的话，接受 CPU 混合的速度下降。
  4. 别盲目开 128K：Qwen2.5 原生支持 128K 上下文，但那需要几十 GB 显存。

怎么调整上下文长度#

Ollama 端通过 num_ctx 参数控制。在 OpenClaw 里配置：

{
  "params": { "num_ctx": 16384, "keep_alive": "15m" }
}

或直接在 Ollama 的 Modelfile 里设置。

小结#

12GB 显存跑 14B 模型的甜蜜点是 8K-16K 上下文。想要长上下文要么换更大显存（24G+），要么接受 CPU 混合的速度代价。本地模型不是越大越好，合适的才是对的。
