OpenClaw 部署实战：用本地大模型搭一个个人 AI 助手

OpenClaw 2026.9.5 在 Windows 上的完整部署过程，对接本地 Ollama 的 Qwen2.5-14B，踩了哪些坑。
September 21, 2026 · 2 min · Local AI Lab

OpenClaw 是什么#

OpenClaw 是一个开源的 AI Agent Gateway（网关），跑在你自己的机器上，把聊天渠道（Telegram、Discord、飞书、Web UI 等）接到大模型。开源协议 MIT，GitHub 上有几十万 Star。

它的价值在于：你发一条消息，它调用模型、执行工具、维护会话和记忆——本质是把"命令行里的 ollama"升级成一个真正能干活的助手。

系统要求#

  • Node.js ≥ 24.16（注意：Node 22 LTS 不够，会被 preinstall 脚本直接拒绝）
  • Windows 10/11
  • 一个本地或远程的 Ollama 实例

安装步骤#

1. 安装 Node.js 24#

从 nodejs.org 下载 Windows zip 版，解压到 C:\nodejs，加入用户 PATH。

[Environment]::SetEnvironmentVariable('Path', "$env:Path;C:\nodejs", 'User')

2. 全局安装 OpenClaw#

npm install -g openclaw@latest

踩坑 1：npm 11 引入了 allow-scripts 安全机制，默认会跳过 koffi 等原生模块的 postinstall 脚本。必须执行：

npm install -g --allow-scripts=openclaw,@google/genai,koffi,tree-sitter-bash,protobufjs openclaw@latest

否则启动时会因为缺少原生绑定而报错。

3. 配置本地 Ollama#

编辑 C:\Users\<你>\.openclaw\openclaw.json：

{
  "gateway": { "mode": "local" },
  "models": {
    "providers": {
      "ollama": {
        "baseUrl": "http://127.0.0.1:11434",
        "models": [
          {
            "id": "qwen2.5:14b",
            "contextWindow": 32768,
            "params": { "num_ctx": 32768, "keep_alive": "15m" }
          }
        ]
      }
    }
  },
  "agents": {
    "defaults": { "model": { "primary": "ollama/qwen2.5:14b" } }
  }
}

踩坑 2：OpenClaw 的 Ollama provider 必须用原生 API（baseUrl 不带 /v1）。用了 OpenAI 兼容的 /v1 端点会导致工具调用失败。

踩坑 3：API key 不写在配置文件里就够了——它存在本地 SQLite 认证库里。第一次运行要执行：

"ollama-local" | openclaw models auth paste-api-key --provider ollama

4. 启动 Gateway#

openclaw gateway install   # 安装为开机自启
openclaw gateway restart

打开浏览器访问 http://127.0.0.1:18789/，用 openclaw gateway auth-token --show 输出的令牌登录，就能在 Web UI 里聊天了。

实测效果#

用 qwen2.5:14b 作为后端，12G 显存下：

  • 普通对话 100% GPU，约 49 tok/s
  • 长上下文（32K）会有部分层溢出到内存，速度下降
  • Agent 模式（带工具调用）功能完整，但 14B 模型对复杂多步工具链的理解不如 GPT-4 级别模型

小结#

OpenClaw 是目前把本地模型包装成"真助手"最省事的方案。部署过程比想象中折腾（Node 版本、npm 安全机制、上下文窗口三个坑），但跑通后就是一个能开机自启、能 Web UI 聊天、能接 Telegram/飞书的完整本地 Agent。
