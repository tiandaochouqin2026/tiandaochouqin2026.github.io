Windows 部署 Ollama 踩坑记录：GitHub 下载失败、局域网访问、OLLAMA_HOST

在 Windows 上部署 Ollama 遇到的三个真实坑：国内网络下载失败、默认只监听回环、OLLAMA_HOST 设置后服务不重启。
September 21, 2026 · 2 min · Local AI Lab

部署本地 Ollama 看起来是一件"下一步下一步"的事，但实际会遇到三个不写出来你想不到的坑。记录一下。

坑 1：官网下载直连 GitHub 失败#

症状：访问 https://ollama.com/download/OllamaSetup.exe，PowerShell 报 Could not resolve host: github.com 或 无法连接到远程服务器。

原因：Ollama 官网只是个跳转页，真正的安装包托管在 GitHub Release。国内网络访问 GitHub 不稳定，时好时坏。

解法：

  1. 先 https://api.github.com/repos/ollama/ollama/releases/latest 拿最新版本号
  2. 在 GitHub 下载链接前加镜像前缀，如： 
    https://ghproxy.net/https://github.com/ollama/ollama/releases/download/vX.Y.Z/OllamaSetup.exe
  3. 用 curl 或浏览器下载，验证文件大小（Ollama 安装包约 1.4GB）

坑 2：默认只监听 127.0.0.1，手机/其他电脑访问不到#

症状：Ollama 跑起来了，本机 curl http://127.0.0.1:11434/api/tags 正常，但 http://192.168.x.x:11434/api/tags 直接拒绝连接。

原因：Ollama 默认 OLLAMA_HOST=127.0.0.1，出于安全考虑不开放到局域网。

解法（PowerShell 管理员）：

[Environment]::SetEnvironmentVariable('OLLAMA_HOST','0.0.0.0','User')

然后必须重启 Ollama 服务才生效。任务管理器里结束所有 ollama.exe 进程，再启动 Ollama 应用。

用 netstat -ano | findstr 11434 确认监听地址变成 0.0.0.0:11434。

坑 3：环境变量设置了但服务没读到#

症状：设置了 OLLAMA_HOST=0.0.0.0，重启 Ollama 后仍然监听 127.0.0.1。

原因：Ollama Windows 版是托盘应用（ollama app.exe），它启动时继承的是登录时的环境。改完用户级环境变量后，必须完全退出托盘应用（右键托盘图标 → Quit），再重新打开。仅重启命令行 ollama serve 会继承当前 shell 的环境，但托盘应用不会。

解法：

  • 检查任务管理器，确保没有残留的 ollama.exe 进程
  • 从开始菜单重新启动 Ollama
  • 用 netstat 验证

坑 4：Windows 防火墙拦截外部访问#

症状：本机用 http://192.168.x.x:11434 能通，但手机连不上。

原因：Windows Defender 防火墙默认阻止外部入站连接到 11434 端口。

解法（PowerShell 管理员）：

New-NetFirewallRule -DisplayName "Ollama" -Direction Inbound -LocalPort 11434 -Protocol TCP -Action Allow

只对局域网开放更安全：

New-NetFirewallRule -DisplayName "Ollama LAN" -Direction Inbound -LocalPort 11434 -Protocol TCP -RemoteAddress 192.168.0.0/16 -Action Allow

小结#

四个坑都不是 Ollama 本身的 bug，而是"本地服务暴露到网络"这件事在 Windows 上的常规障碍。按顺序：下载镜像 → 改 OLLAMA_HOST → 完全重启 → 防火墙放行。踩完一次，下次 10 分钟搞定。
